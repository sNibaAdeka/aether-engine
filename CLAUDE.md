# AETHER — памятка по проекту

Процедурный фотореалистичный открытый мир на three.js + WebGPU. ТЗ: `AETHER_WORLD_SPEC.md`
(в `~/Downloads`). Журнал фаз: `PROGRESS.md` — **обновлять в конце каждой фазы**.

## Стек

TypeScript 5.9 strict · Vite 6 · three r185 (`three/webgpu` + `three/tsl`) · Rapier3D ·
Vitest · Playwright. Алиас `@/` → `src/`.

## Команды

```
npm run dev         # dev-сервер, http://localhost:5173
npm run typecheck   # tsc --noEmit, должен быть чистым
npm test            # vitest, unit-тесты математики
npm run shot        # Playwright: все 6 эталонных ракурсов → .screenshots/
npm run shot -- --preset=valley-dawn --quality=ultra
npm run build       # typecheck + vite build
```

`npm run shot` пишет рядом с PNG ещё и `.md` с таймингами профайлера и консольными
ошибками. **Смотреть PNG глазами через Read** — это единственный настоящий критерий.

## Архитектура

- `Engine` владеет циклом, рендерером и упорядоченным списком `System`.
- `System` = `{ name, init, update, prepare?, dispose }`. Порядок явный, без приоритетов.
- `FrameGraph` — фиксированный список проходов (`PASS_ORDER`), с амортизацией (`cadence`).
- `Clock` — fixed timestep 1/60, аккумулятор, максимум 5 подшагов. `elapsedShader`
  сворачивается по модулю ≈3600 с (кратно 2π), чтобы f32 в шейдерах не поплыл.
- `Profiler` — кольцевой буфер 120 кадров, p50/p95 по секциям. `Settings` — единственный
  источник правды по качеству; на него подписаны все системы.
- `window.__AETHER_DEBUG__` (`src/debug/DebugBridge.ts`) — контрольная поверхность для
  Playwright: `setCamera`, `setTimeOfDay`, `setWeather`, `waitFrames`, `timings`, `errors`.

## Жёсткие правила

1. **Никаких аллокаций в `update`.** Временные объекты — модульные `const _v3 = new Vector3()`.
2. **Данные — плоские типизированные массивы**, не массивы объектов.
3. **CPU- и GPU-версии высоты обязаны совпадать** с точностью 0.05 м. `src/math/Noise.ts`
   и WGSL-двойник меняются только вместе.
4. Всё, что можно посчитать на GPU, считается на GPU. CPU — стриминг, физика, звук.
5. Ambient берётся из атмосферы, никогда не константа.
6. AO применяется только к непрямому свету.
7. Заглушки помечаются `// TODO(quality):` и попадают в `PROGRESS.md`. Не писать
   «реализовано» про пустышку.

## Текущая фаза

**Фаза 3 — атмосфера и небо реализованы.** Весь свет в сцене выводится из
модели рассеяния Bruneton/Hillaire: четыре LUT (transmittance 256×64 и
multiple-scattering 32×32 — один раз; sky-view 200×100 и фроксель
аэроперспективы 32³ — каждый кадр), солнце и луна из настоящей астрономии
(`math/Spherical.ts`, `world/TimeOfDay.ts`), ambient — sky-view LUT, спроецированный
на SH L2 в compute и подставленный в `THREE.LightProbe`. Провизорный свет из
`DebugScene` удалён целиком. Аэроперспектива подключена через `scene.fogNode`,
поэтому её получают все материалы с `fog = true`, включая будущие фазы 6–7.

Кадр рисуется в линейный HDR-таргет в кд/м², гистограмма 256 бинов в compute
даёт EV100 по полосе 40–95 перцентиля, адаптация 0.8 с / 2.5 с, тонмаппинг AgX
со сдвигом Пуркинье. Экспозиция не покидает GPU.

Замерено чередующимся A/B (медиана парных разностей, 6 повторов): небо
+0.10 мс при бюджете 0.20, LUT кадра +0.20 при бюджете 0.30, аэроперспектива и
звёзды ниже разрешения таймера. Полный кадр вырос на ~0.9 мс против сборки
фазы 2, замеренной в том же сеансе. Память 151.6 МБ из 160 — **запаса
осталось 8 МБ**, и HDR-таргет растёт с разрешением; это первый долг, который
придётся закрыть.

Открытый долг №1 прежний — щели и полупрозрачные «плёнки» на швах и границах
LOD (фазы 1b/2); проверено `git stash`, они есть и до фазы 3. Полный список —
в `PROGRESS.md`, раздел «Фаза 3».
